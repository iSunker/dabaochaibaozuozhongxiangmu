## 一、这是什么

三份大文档（`README` / `SUMMARY` / `ENVIRONMENT`）是**唯一事实源**。它们太大，检索靠人眼。
`tools/doc-audit/` 干的事不是拆文档，是**给它们做投影**：

```
        ┌─ 事实源（唯一）──────────────────────────┐
        │  README.md   SUMMARY.md   ENVIRONMENT.md │
        └───────────────────┬──────────────────────┘
                            │  只读，可反复跑
        ┌───────────────────┴──────────────────────┐
        │  01_headings  → out/headings.tsv   结构树 │
        │  02_refs      → out/refs.tsv       引用表 │
        │  03_terms     → out/terms.tsv      倒排表 │
        │  04_probes    → out/probes.tsv     事实表 │
        └──────────────────────────────────────────┘
```

**投影只读事实源，事实源不读投影。** 这条方向不能反过来 —— 一旦反了就成了环，两边都会漂。

`out/` 全在 `.gitignore` 里：它们是**可反复生成的派生数据**，冻进仓库只会变成一条会漂的"事实"。

## 二、四份投影各自什么时候用

| 脚本 | 产出 | 什么时候用 | 判据（健康长什么样） |
|---|---|---|---|
| `01_headings.py` | `out/headings.tsv`<br>file / level / line / slug / title / parent | ① 加章加节后看层级有没有跳<br>② 想知道某节在哪一层 | **0 个层级跳跃**；**0 处围栏缺陷** |
| `02_refs.py` | `out/refs.tsv`<br>src / line / ref / status / target / hint | ★ **改完任何标题、或挪动任何章节之后必跑** | **悬空 0**、半悬空 0、锚点无命中 0、锚点歧义 0 |
| `03_terms.py` | `out/terms.tsv`<br>term / file / line / context | 找「同一事实散在多处」的嫌疑；或某个常量改名前先看它散在哪 | 跨 ≥2 文件的关键词**逐个有人认领**（认领 = 该留的留、该并的并） |

```bash

python tools/doc-audit/03_terms.py
python tools/doc-audit/04_probes.py
```

### `02_refs.py` 管的六族锚点

改标题之前先知道哪些东西挂在标题上：

| 族 | 形态 | 目标在哪 |
|---|---|---|
| ① | `§N` / `§N.M` / `§N.M.K` | SUMMARY 的编号标题（`## 19.` / `### 19.1` / `## §20.8` 都认） |
| ② | `ERR-XX-NN` | `ENVIRONMENT.md` 的 H3 条目 |
| ③ | `README「…」` / `ENVIRONMENT「…」` | 对应文档的标题（**子串命中且必须唯一**） |
| ④ | `A.N` / `B.N` | `ENVIRONMENT.md` 自己的 H2 |
| ⑤ | `弯路 #N` → **LEGACY** | `走过的弯路.md` 已拆（`373b1ea`）⇒ **不可能命中标题**，靠 `ENVIRONMENT.md` 顶部那条反查 grep 解析。**故意不计进悬空**，否则 20 条真引用会被 20 条假警报淹掉 |
| ⑥ | 围栏内的引用 | **不算** —— 代码示例里的 `§N` 是示例，不是引用 |

### ★ 为什么跑围栏要按 CommonMark，不能"见到 ``` 就翻"

`SUMMARY.md` 的 **L5478** 曾经是 `**已沉淀成工具**：```` —— 三个反引号在**行尾**。
CommonMark 说这是**内联代码**，而它会把**下一行的裸 ``` 一起吃掉**。

⇒ 「见到 ``` 就翻」的解析器从那一行起**永久错位**，一路把后面 100+ 个真标题当成代码块内容吞掉。
实测：同一个缺陷骗了两套写法（朴素翻转数出 206，第一版"严格围栏"数出 321，**真值是 340**）。

所以走行逻辑抽在 **`mdwalk.py`** 里，四份脚本共用 —— **不做四份会各自漂的拷贝**。
它还会在收尾时**报围栏缺陷**，而不是闷头算错。

## 五、已知的硬限制（别指望它做这些）

| 限制 | 说明 |
|---|---|
| **看不见"层次感"以外的东西** | `01` 只判层级跳跃，判不出「这一节放错了文档」。职责审计要人过 |
| **两套写法都能解析 ≠ 两套写法都对** | `02_refs` 同时认 `## 21.` 和 `## §21`，所以**写法不统一它不报**（见 `#88`） |
| **`弯路 #N` 是 LEGACY** | 它已无标题可指，靠 grep 反查。**新增引用不要再用这个形状** |
| **探针只读，不判对错** | 它把生产读出来，**"文档声称 vs 实读"的比对仍是人来做的** |
| **NAS 侧那几条做不到** | 无 SSH ⇒ 容器环境变量、`synoschedtask`、真发邮件这几类**探针做不了**，只能走"等价物"（如容器 env → `cross-seed.db` 的 `indexer` 表） |
| ★ **只扫仓库根的 `*.md`** | `01`/`02`/`03` 的 `DOCS` 是**仓库根**（`tools/`、`tests/` 下的 md **不在范围内**）。所以 `tests/README.md` 与**本文档自己**的引用**没人查** —— 往这两处写 `§N` 之前，自己先确认目标在 |

## 六、安全纪律（改这些脚本时**必须守住**）

**两条都要有，缺一条就是漏洞：**

1. **不选可能含凭据的列。**
   `cross-seed.db` 的 `indexer.url` **每条都带 `apikey=<Prowlarr 应用级 key>`**，
   那个 key 能开 Prowlarr 上**所有 PT 站**。判「哪个站、什么状态」靠 `id` / `name` / `status` 就够，
   `url` 对判读**零价值**。**能不取就不取** —— 这是主防线。

2. **出口统一过 `redact()`。**
   万一某个探针必须碰这类列，或异常信息里带出来，在**打印和落盘之前**按**值的形状**抹掉。
   按**键名**匹配会漏掉嵌在 `options` / `fields` / 异常文本里的凭据 ⇒ 兜底要按形状。

> 判据是「**只读 + 不回显凭据 + 只打聚合**」这三条同时成立 ——
> 与 `check-deploy-drift.py` 里 `qb-census` / `linkguard` 那两条**同一个形状**。
> 不是「它碰没碰凭据」—— 后者会把所有有用的诊断工具都挡在门外。

另外：**探针一律只读**。库用 `query_only`，UNC 直读、**不 `cp` 副本**（WAL 里未 checkpoint 的数据会丢）。
