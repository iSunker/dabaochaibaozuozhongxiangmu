## 29.3 ★★★ 本轮唯一的真缺陷：**判据在最该报的时候哑掉**

### 现象与根因（本机实测复现，不是推断）

`scripts/diag/drive-loop-mount-selfcheck.sh` ② 段的 **python heredoc** 里：

```python
print("  %s pack=%-18s %-9s %s" % ("✓" if e_ else "✗", r["name"], k, v))
```

`✓` / `✗` 是 **U+2713 / U+2717**，而 **Windows 上 python 默认 stdout 编码是 GBK**
⇒ 编不出 ⇒ `UnicodeEncodeError`。

★★★ **症状不是"整个脚本崩掉"**（那样反而显眼），是 **② 段半途而废**：

```
② state.db 里的**绝对路径**（这才是 1:1 挂载的实质）
Traceback (most recent call last):
  ...
UnicodeEncodeError: 'gbk' codec can't encode character '✗' in position 2
③ .env 里的路径前缀 vs 挂载点          ← ★ ② 段就这么没了
```

- **前面的 `✓` 行都打完了**（U+2713 在 GBK 里也编不出，但只要**第一条是 `✓`**
  且那条**真的走了 `print`**……见下"为什么是"第一条 ✗"）——
- 一到**第一条 `✗`** —— 也就是**真有问题、最该被看到**的那一行 —— **就抛**；
- ⇒ 那一段的**全部裁决** + `⇒ 路径不可达数` **一行都出不来**，只剩一段 traceback；
- 而 heredoc 那支 `|| RC=1` **又兜住了退出码** ⇒ **脚本以 1 退出却不给解释**。

★★ **所以：判据恰好在最该报的时候哑掉。** 这是本项目最怕的形状
（`ERR-AI-07` 同族：**读不到 ≠ 通过**；这里更糟 —— **读到了问题却报不出来**）。

> ★ 附一条**实验边界**（如实写）：`✓` 与 `✗` **在 GBK 下都编不出**，
> 所以严格说，只要那一段走到**任意**一行就会炸。本例里之所以"前面几行是 `✓`、
> 到第一条 `✗` 才炸"，是因为**那些 `✓` 来自 shell 的 `ok()`（printf）**，
> 而 **printf 不过 python 的编码器**（见下）。⇒ **"shell 打的 ✓ 没事、
> python 打的第一行就炸"** —— 这正是下面那条反向判据的来源。

### 处置：**照抄，不是新设计**

```sh
export PYTHONIOENCODING=utf-8
```

★ 本仓**早就有先例**，而且**头注里记的正是同一个毛病**：

- `chk58.sh:107` —— 已带着这句；其头注第 ④ 条原文：
  「python heredoc 里打了 U+21D2，GBK 控制台编不出 ⇒ python 抛
  `UnicodeEncodeError` **整个脚本段崩掉**」
- `scripts/drive-loop-nas.sh` / `scripts/drive-loop-resident.sh` —— 同句。
- ⇒ **`mount-selfcheck.sh` 是重建时漏抄了那一条**。

★★ **这又是"同一个切换里漏改了一个"的第 N 个实例**（同 §19.1.3 的形状）：
`chk58.sh` **重建时记得加**、`mount-selfcheck.sh` **重建时没加** ——
而两份的**其余部分高度同构**（都在 NAS 上跑、都用 python 读 `state.db`）。
**判据不是"抄了没有"，是"两个同构件的行为是否一致"。**

### ★★ 反向判据：**shell 那侧的 `printf` 不需要这条**（这条比正面更值钱）

实测：

python -c 'print("  ✗ python")'    ⇒   UnicodeEncodeError

⇒ ★★ **别把「给 shell 也加一条」当补强** —— 那是**把判据钉在一个不存在的失效模式上**

`mount-selfcheck.sh` 的 `bad()` / `ok()` 用的是 `printf`，**本来就没事**。

⇒ **本次只改一处**，不是"三个一起扫"—— 这个区别要写出来，否则下一个人会
要么白扫两个、要么以为"扫过了"。

| `cat .drive-loop.state` ⇒ `phase:"running"` | 第一次 | 我据此断言「有缺陷」 |
| **同一条命令**再读 ⇒ `phase:"idle"` | **7 分钟后** | 现场从头到尾是对的 |

根因：`phase` **每 60 秒翻一次**（`drive-loop.py:2460` `Heartbeat.__init__(period=60.0)`）。
`running` 是**批次正在跑**时的正常瞬时值；睡眠期被
`Heartbeat(phase=PHASE_IDLE)` 覆盖成 `idle`（`drive-loop.py:3062` 那个 `with`）。
⇒ ★★ **`cat` 一次 `.drive-loop.state` 不是有效的取证动作** ——
它取的是**一帧**，而这个字段**每拍就翻**。判「卡没卡」那类问题，
本仓已有正确形态（`ERR-SCHED-09`：只有日志能分开"退避 / 卡死"），
而**取状态文件必须是"两个时刻各读一次"**，不是一次。

★ **这条与 §28.6 同族、方向相同**：那条是「把**单点观测**当时刻表」，
这条是「把**单帧读数**当稳定状态」。两次都栽在**同一个动作**上 ——
**把一个瞬间的观测提升成了规律**。

#### ★★ 顺带查清的一件事：`phase` 与 `mode` **正交**，不是同义词

`drive-loop.py:2411-2416` 的注释写得很清楚，我也**独立读源码核过**：

| 字段 | 语义 | 跨轮变化 |
|---|---|---|
| `mode` | **上次是哪条路**（身份：`resident` / 空） | 只有常驻分支写，**基本不变** |
| `phase` | **现在在干什么**（`idle` / `running`） | **每轮翻转**，每次心跳都写 |

⇒ 所以是**两个字段**而不是一个（`_resident_state` 的注释原话：「不新造同义词」）。

#### ★★ 所以本轮**不修任何东西**，钉的是「别让将来的人把它改成 `running`」

**那个我*以为*存在的缺陷，形状是这样的**（真改成 `running` 才会发生）：

* `_resident_state()` 的 `phase` 形参有**一处默认值**（`drive-loop.py:2944`
  `phase: str = PHASE_IDLE`）；
* 而它**四处调用里有三处不传参** —— `drive-loop.py` 现读：`:2969` 启动、
  `:2992` dry-run、`:3035` 本批无动作；
* ⇒ **默认值写错 = 三处同时写错**，症状是「永远判在跑 ⇒ 静默永久停工」
  —— 正是 `Heartbeat` docstring 里最怕的那个。

#### 回归：`tests/test_drive_loop_service.py` ⑨ 段 **+16（83 → 99）**

| 断言 | 钉什么 |
|---|---|
| ⑨a / ⑨a-2 | `_resident_state` 的 `phase` 默认值是 `PHASE_IDLE`，且**有**默认值（没有 ⇒ 三处不传参当场 `TypeError`） |
| ⑨b ×6 | `once_round` / `main` 的**收尾那次**、`_resident_state` 的**每轮快照**，`write_state({...})` 字面量里**都含 `"phase"`** |
| ⑨c-1 / ⑨c-2 | ★★ **反向两条**：`running`+心跳新鲜 ⇒ **True**（正常在跑的**绝不许**判成可接管 —— 两批并发发 webhook ⇒ 一次 429 废几百条，README 坑 4）；`running`+心跳陈旧 ⇒ **False**（卡死**必须**能被接管，否则 autoheal 那套白装） |

**★ 为什么判据用 `ast` 读 `defaults`，不用字符串匹配**：
字符串匹配**分不出**「默认值是 `idle`」和「注释里写了 `idle`」
（`drive-loop.py` 里那段解释 `phase` 的注释恰好就写着 `PHASE_IDLE`）。

**★ 为什么要用「整体覆盖」这条性质**：三处 `write_state({...})` 都是
**字典字面量、不是 `{**st, ...}` 合并** ⇒ **不写 `phase` 就等于删掉它**
⇒ 下一个读者走「旧格式」分支（只信心跳）⇒ 「说在跑的那位早收工了」**检测不到**。
（**不是**「值写错了」，而是**键整个没了** —— 这个失效模式不看代码看不出来。）

##### ★★ 写这段时栽的两次（都值得逐字记，因为**两次栽在同一个地方**）

**两次都栽在「怎么算'收尾那个'」上**：

| 版本 | 写法 | 结果 |
|---|---|---|
| 第二版 | `ast.walk` 的**出现顺序**取"最后一个" | ❌ `main()` 里取到的是**嵌套函数 `_resident_state` 的 `write_state`**（L2957），**不是**常驻分支真正的收尾（**L3073**）⇒ 削掉 L3073 的 `phase` 之后**断言照样过** |
| 第三版 | **按 `lineno` 排序** + 用**结构特征**指名收尾 | ✅ |

**特征比位置稳** —— 位置法已经栽过两次了。
