## §24 SUMMARY 按章拆分 + 本轮收口（2026-09-16）

> 本章记两件事：**① 把 SUMMARY 拆成「入口 + summary/ 24 章」这件事本身**
> （为什么拆、怎么保证无损、拆完动过什么口径），
> **② 靠这次拆分才暴露出来的两处「判据自己坏了」**。
> ★ 本章是分章之后**第一次按新流程追加的章** —— 所以它同时是那条流程的活样本。

### 24.1 为什么拆：`字面无损压缩`做不到，能做的是「别整份读」

起因是一句很朴素的需求：**「这三份 md 太大了，读起来很费 token，能不能无损压缩？」**

先把问题问清楚，结论分两层：

| 层 | 结论 | 依据 |
|---|---|---|
| **字面意义的「无损压缩」** | ★ **做不到，已定论** | 三份文档**全量重复率 0.1%**（#113 实测定论）⇒ 没有可压的冗余 |
| **能不能少花钱读** | ✅ **能，而且余量很大** | 成本**不在文件大，在「整份读」这个动作** |

第二层的量级（实测，不是估计）：

- 体积分布：**SUMMARY 一家占三份总量的 62%**（516 KB / 8305 行）；
- 代码围栏占比只有 **README 9.3% / SUMMARY 12.4% / ENVIRONMENT 1.5%**
  ⇒ **87~90% 是散文**，而每一句都是踩坑记录（删不掉）；
- 于是「查一个局部问题」的最坏代价 = **吞下 516 KB**。

★ 所以这次**压的不是文件，是「整份读」这个动作**。

### 24.2 拆法：入口 + 分章，且**必须逐字节无损**

```
SUMMARY.md（入口）    L1..导航结束 → 导航 + 「§N → 文件」表（101 行 / 10.5 KB）
summary/NN-<短名>.md  §0..§24 共 25 章
```

**无损是可机器证明的承诺，不是口头保证：**

```bash
cat summary/*.md | cmp - <(git show <父提交>:SUMMARY.md | tail -n +91)   # 必须相同
```

★ 原始文本**永久可从 git 历史取回**（`git show <父提交>:SUMMARY.md`）——
这是"无损"的兜底：即使 summary/ 全丢了，正文也没丢。

### 24.3 ★ 表里只放「§N → 文件」，**不放行号**

这一条是**决策时最吃劲的地方**，理由值得单独记：

| 方案 | 为什么会烂 |
|---|---|
| 索引表带**行号区间** | 行号**会随每次编辑静默作废** —— 而这文档**每周都在改**。失效时**不报错**，只是指到错的地方 |
| ✅ **§N → 文件** | 文件映射**只在新加章时**才变；改了某章内容，映射**照旧成立** |

★ 这条决策的收益当场兑现了：现在追加 §24 只改**一行表**，**一处行号都不用动**。

### 24.4 为什么拆分是安全的：**引用按 §N 寻址，不按路径**

拆分**不重编号**、**不改标题**、**不动一个正文字节** ⇒ 全仓库 `SUMMARY §N`
跨文档引用**一处都不用改**。

> ★ **本处原写「476 处」，2026-09-16 实测更正为约 690 处**（`02_refs` 的 `ref` 列以 `§` 开头者，
> **全仓库口径**）。★ **不在这里写死精确数**：本节自己引 `§N`，写一次数就变一次
> ⇒ 精确值一律**现跑** `python tools/doc-audit/02_refs.py`（本条初写时就撞过一次：
> 记 692，加了这段说明之后变成 693）。
> 那个 476 是**分章前另一个口径**的读数（当时只数 SUMMARY 一个文件里的 `§` 字符出现次数 = 472），
> **不是同一件事** —— 「字符级出现次数」与「引用级计数」不可比。改这回是为了不让一个
> 传抄来的数变成事实（同 §24.10② 与 `ENVIRONMENT` 那条「措辞一旦成断言就成假事实」）。

★ 这不是推断，是 **A/B 实测**（分章前 vs 分章后，用 doc-audit 投影对跑）：

| 读数 | 分章前 | 分章后 |
|---|---|---|
| 标题总数 | 573 | **573** |
| 引用总数 | 1048 | **1048** |
| 目标集合（编号标题 / ERR / A-B / README / ENV） | 316 / 108 / 22 / 58 / 162 | **完全相同** |
| 悬空 / 半悬空 / 锚点无命中 / 锚点歧义 | 0 / 0 / 0 / 0 | **0 / 0 / 0 / 0** |

### 24.5 ★★ 拆分逼出的第一处：**三个脚本的 glob 口径会「静默」漏掉 24 章**

分章把**投影的输入集合从 3 个文件变成 27 个**。而 `01`/`02`/`03` 当时各自写着
`glob("*.md")`（**非递归**）—— 于是：

| 脚本 | 漏掉之后会怎样 |
|---|---|
| `01_headings` | 24 章的全部标题从结构树里**消失**（573 → 349） |
| `02_refs` | 目标集合建不起来 ⇒ **全部 §N 引用全被判成「悬空」** |
| `03_terms` | 倒排表少 24 个文件 |

★★ **三个都不会报错** —— 工具照样跑完、照样输出一张**看起来很正常的表**。
这正是本仓反复记档的最防形状：**命令成功了、结论是错的**。

**修法**：口径**只在 `mdwalk.doc_files()` 一处定义**，三个脚本共用：

```python
def doc_files(root):
    return sorted(list(root.glob("*.md")) + list(root.glob("summary/*.md")))
```

★ **显式两条 glob，不用 `rglob`** —— `rglob` 会把 `tests/`、`patches/`、`tools/` 下的
`.md` 一并收进来，那是**另一种**悄悄改口径。宁可写死两条，也不要一个"顺便多收"的聚合。

### 24.6 ★★ 拆分逼出的第二处：`01_headings` 的「层级跳跃」判据**恒报 24 条**

分章后 `01` 开始对**每一个** `summary/NN-*.md` 报：

```
[!] 层级跳跃 08-安全约定.md:1 h0→h2 '8. 安全约定（务必遵守）'
```

**成因不是缺陷**：每个章文件都是**碎片** —— 从 `## N.` 开头、自己**没有 h1**
（h1 在入口 `SUMMARY.md` 里）。拼回去层级是完整的，**单独看却必然报「h0→h2」**。

但它的代价是实的：`INDEX-USAGE.md` 把「**0 个层级跳跃**」写成健康判据，
而它现在**恒为 24** ⇒ 一条**恒红的哨兵**。
★ 按本仓自己的规矩（`SUMMARY` §15.5 那条）——「**一个会误报的哨兵，两次之后就没人看了**」。

**三个候选与取舍**：

| 方案 | 为什么不选 / 选 |
|---|---|
| 每章加一个 h1 | ❌ ★ **破坏「正文一字未改」** —— 那些字节不再来自原文，`split-summary.py` 的无损自检再也过不了 |
| 只在文档里写明「24 是基线」 | ❌ **判据失去分辨力** —— 真出现**第 25 条**真跳跃时，会被淹在这 24 条里 |
| ✅ **改 `01` 判据：碎片文件不报** | 判据绑在「**文件自身有没有 h1**」上，不是写死目录名 |

**选的是第三条**，判据本体：

```python
rooted = any(lvl == 1 for _, lvl, _, _, _, _ in rows)   # 文件里出现过 h1 ⇒ 它是完整文档
for ...:
    if rooted and lvl > prev + 1:      # 碎片（无 h1）天然豁免
        print("[!] 层级跳跃 ...")
```

★ **为什么不写死 `summary/` 这个目录名**：那样口径就绑在**路径**上 ——
将来换个目录名、或再拆一层，这条豁免会**静默失效**（又退回 24 条假警报）。
绑在「有没有 h1」这个**文件自身的性质**上，则**新碎片自动豁免、真缺陷照样报**。

**验收（双向，缺一不可）**：

| 检验 | 期望 | 实测 |
|---|---|---|
| 真仓库跳跃数 | 0 | **0** ✓ |
| 真仓库标题总数 | **不变（573）** | **573** ✓ |
| 阴性对照：有 h1 的文件里 h1→h3 | **必须报** | 报出来了 ✓ |
| 阴性对照：无 h1 的碎片从 h3 起 | **豁免** | 豁免 ✓ |

★★ 第三、四条**必须成对做**：只验"不报了"是**假测试** —— 把判据整个删掉也能过。
要有"该报的还报"作对照，才证明改动**只豁免了碎片**。

### 24.7 分章之后，这两件事的**口径变了**（别拿旧读数对）

| 东西 | 分章前 | 分章后 | 属于哪种变化 |
|---|---|---|---|
| 投影输入文件数 | 3 | **27** | 口径变宽 |
| `03_terms` 的「跨 ≥2 文件」 | 25 个词 | 会**变多** | ★ **不是新重复** —— 同一章内两处命中以前算 1 个文件，现在跨章算 2 个 |
| `headings/refs/terms` 的**内容列** hash | — | **全变** | file 列进了内容列（`SUMMARY.md` → `21-….md`） |

★ 所以 **09-13 那份基线对分章后的仓库不再可比** —— 见 **#101**（重冻），

### 24.8 分章自己的两个坑（**是「假测试」形状，与 §18.10.1 同源**）

#### ① `b"\n".join(切片)` **不给末行补换行**

`b"\n"` 是**切到下一块去的分隔符**，**不跟着块走**。于是每个章文件都缺收尾换行，
`cat` 拼起来就把**每章末尾的空行并进了下一章的标题行**（`---\r\n` + `\r` + `## 1. …`）。

实测：**正好少 23 行 / 23 字节** = 23 个章间边界。修法：每块显式 `+ b"\n"`。

#### ② ★★ **自检与 bug 自洽 ⇒ 永远绿**

第一版的无损自检写的是 `rebuilt = b"\n".join(chunks)` ——
这**恰好把上面漏掉的收尾 `\n` 又补了回来**，于是"重建"与"期望"当然相等：

> **判据用了与落盘不同的字节去拼，于是 dry-run 两条自检全过、而落盘的文件是错的。**

**只有独立的 `cmp` 才揭穿了它**（`differ: byte 9956, line 113`）。

⇒ 修法：自检**必须用与落盘完全相同的字节**去拼，即 `b"".join(...)`；
并加 `assert body.endswith(b"\n")` 钉住形状。
★ 这是本仓「**假测试**」形状的又一实例：**判据自己也是被测对象**。

### 24.9 一条被漏掉的事后收口：**`--apply` 之后 SUMMARY 并没被截**

第一版把「切分」和「截断入口」算成了同一件事。于是补完入口表就以为完事了 ——
**正文在两个地方各留了一份**。doc-audit 当场看出来：**标题 573 → 924**（各章被数两遍）、
引用 1048 → 1458。

★ 根因值得记：**「切分无损」与「入口已更新」是两条不同的断言**，
而当时那条 `cmp` **只证明了前者**。

修法：单独一步 `--truncate-entry`，且**截断前先验证**
「待删的正文 ⇔ `summary/` 全部文件的拼接」**逐字节相同** —— 对不上就**拒绝截断**
（此时截断 = 静默丢数据）。

### 24.10 本轮的另两处修正（**都不在拆分本身**）

#### ① `#115` 的现场读数：**新分支一次都没被走到**（不算通过也不算失败）

`wait_out_backoff` 的新判据是「**还有健康站就照发**」。2026-09-16 08:38 UTC 读 `drive-loop.log`：

- 16:15 那批（= 08:15 UTC）已跑完：**成功 50 / 失败 0**，但**没有退避**；
- **全日志 `不等，照发` = 0 命中**；
- 当天**所有批次 `失败 0`**，只有两处退避且**都很短**（HDFans 15 秒）；
  另两处 HDtime/NanyangPT 的"解禁时刻"**早于记录时刻** ⇒ 是**已过期的残留标签**，不是真在等。

⇒ **全天没有一次「单站退避 > 30 分钟」** = 触发条件没发生 ⇒ **验收悬置**。
★ 这条教训与 §20.3 同源：**「没响」有多个来源**，不能读成「没事」，
也不能读成「生效了」—— 得先确认**触发条件是否发生**。

#### ② `#114` 顺带要看的：同一个函数里两种时刻格式

`state.py` 里「解禁时刻」有**两种**打印格式：`2504` 行只有 `%H:%M:%S`（**无日期**）、
`1028` 行与 `drive-loop.py:769` 有 `%m-%d %H:%M`。
**跨午夜就分不清「今天还是明天」** —— `#111` 记的「再禁到 09-16 13:32」与日志里
「要等到 2026-09-16 01:31:11」**差 12 小时**，很可能就是这种读数被传抄成了断言。

### 24.11 本节的方法论（四条）

1. **「无损」要能机器证明，不能靠承诺** —— `cmp` 对着 git 里的旧版本，逐字节。
2. **判据必须用「与落盘完全相同的字节」构成**（§24.8②）——
   否则判据与 bug 可以自洽，**自检永远绿**。
3. **改判据时要成对做对照**（§24.6）—— 只验"不报了"是假测试，
   要有"该报的还报"，才证明改动**只豁免了该豁免的**。
4. **口径只定义一处**（`doc_files()`）—— 三份拷贝就会三处漂；
   而**聚合型写法（`rglob`）是另一种悄悄改口径**，宁可显式写两条。
